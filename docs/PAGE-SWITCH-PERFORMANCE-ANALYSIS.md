# 页面切换慢的根因分析（v1 ↔ v2）

> 日期：2026-11-24
> 分支：perf/table-block-refactor (41e957c655)

## 用户报告

"v2 v1 页面间切换，加载速度慢，特别是 v2 页面，200条/页时响应很慢"

## 核心结论

**切换慢不是表格性能问题，而是架构问题：v1 和 v2 是两个完全独立的 HTML 入口，切换时触发完整页面重新加载。**

## 实测数据（生产模式，13010 端口，dist 构建）

| 切换方式 | 耗时 |
|---|---|
| **v2 SPA 内导航**（菜单点击，v2 页面1 ↔ 页面2） | **165–292 ms** |
| **v1 ↔ v2 整页跳转** | **7,200–7,400 ms** |
| v2 首次加载（含登录） | DOM 3.6s / FCP 9.3s |

**相差约 30 倍。**

## 根因证据链

### 1. 两个独立入口
```
packages/core/app/dist/client/index.html      (v1，17 个 script)
packages/core/app/dist/client/v/index.html    (v2，9 个 script)
```
v1 用 `/admin/<uid>`，v2 用 `/v/admin/<uid>`。两者：
- 不同的 HTML 文件
- 不同的 JS bundle（hash 都不同）
- 不同的 CSS（`/global.css` vs `/v/global.css`）
- 各自独立的 React 应用实例、路由、store

切换 = 浏览器卸载整个旧应用 + 加载新应用（88 个 script 资源 + 23 个 API + 重新初始化）。

### 2. 排除表渲染瓶颈
- CPU profile：切换期间 **(idle) 占 78–96%**，JS 执行几乎为零
- 主线程 long task 仅 1 个（578ms）
- 所有 API < 1 秒（最慢 `app:getLang` 900ms，`perf_table:list` 307ms）
- 资源全部缓存（duration=0）
- 88 个 script 从缓存加载，但每个都要重新**解析执行**

→ 慢在**浏览器导航 + 新应用初始化**，不是表格渲染，不是网络。

### 3. dev 模式更慢（45 秒）
dev 模式切换 45 秒，trace 显示 V8 后台解析 17 个大 JS（单个最长 12 秒）——未压缩 + source map + HMR 运行时。生产模式 7.3 秒，是真实体验的上限参考。

## 为什么 200 条/页时"感觉更慢"

切换后表格要渲染 200 行 × 10 列（2614 cells）。但这部分渲染发生在**应用初始化之后**：
- v2 SPA 内导航到 200 行页面：~200ms（含表格渲染）——很快
- 整页跳转到 200 行页面：7.3s = 应用加载 ~7s + 表格渲染 ~0.2s

所以"200 条/页时慢"的体感主要来自**整页加载基数（7s）**，表格渲染只占很小部分。200 行本身不是切换慢的主因（之前已优化勾选交互 -82%）。

## 可行的优化方向

### 方向 A：消除整页跳转（架构级，收益最大）
让 v1 和 v2 在同一页面内共存/切换：
- 用 iframe 嵌入（v2 页里放 v1 iframe 或反之），避免整页重载
- 或统一到单一入口（把 v1 页面迁移为 v2 页面——官方方向，v2.2 起主推 `/v/`）
- 收益：7.3s → ~0.3s；成本：中~高

### 方向 B：减少新应用初始化开销（工程级）
- 合并/共享 v1、v2 的 vendor chunk（当前各自打包，重复加载 antd/lodash/moment 等）
- 预加载目标入口的 JS（用户点菜单前 prefetch）
- 收益：可能从 7.3s → 3–5s；成本：中

### 方向 C：保持现状，引导用户习惯
- 在 v2 内完成所有工作（内部后台），v1 仅用于遗留页面
- 避免频繁跨入口切换
- 成本：零

## 建议

1. **短期**：接受跨入口切换 7s 的现实（架构限制），把日常操作放在同一入口内；表格交互优化（已完成 -36%/-82%）解决的是页面内的卡顿
2. **中期**：把 v1 页面迁移到 v2（官方方向），统一到 `/v/` 单一入口，彻底消除跨入口切换
3. **不建议**：为切换慢去改表格代码——根因不在表格

## 测试环境说明

- dev 实例：13001 端口（`yarn dev`，代码实时编译，切换 45s）
- 生产实例：13010 端口（`yarn start` + dist，切换 7.3s，代表真实体验）
- 数据库：pg16 `nocobase_perf_test`
